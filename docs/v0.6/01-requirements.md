# v0.6 요구사항

2026-10-22 초안(사용자 확인 전). 같은 반(SKT ALEPH) 수강생이 각자 자기 PC에서 JOBVIS를 Docker로 띄워 쓰게 한다. 웹 공개는 이번 버전에서 하지 않는다.

## 목표

1. 반 사람이 저장소의 compose 파일과 자기 Gemini 키만으로 `docker compose up` 한 번에 화면을 연다.
2. 구글 서비스 계정·시트 설정 없이 쓴다. 결과는 각자 PC 안의 DB에 저장한다.
3. 공고 이미지 OCR이 기본으로 들어 있다.
4. 지금 쓰는 사람(시트 사용)은 설정 한 줄로 기존처럼 시트를 쓴다.

## 사용자 결정 (2026-10-22)

- "각자의 key를 사용해야함"
- "개인 정보는 개인만 보관해야함 (현 sheet 처럼)" → 공유 서버 없음, 각자 PC에 저장
- "반 사람들이 이것을 사용하기 위한 환경 셋팅이 더 쉬워야함"
- "웹 배포는 최후순위로 나중에 결정"
- "모두 Docker를 실습하고 있기에 문제는 없다" → Docker 설치 안내는 넣지 않음
- "OCR은 기본으로 사용하고싶다"
- Mac은 나중에 고려 → 이번 대상은 Windows·Intel(amd64) PC

## 사용 흐름 (반 사람 기준)

1. 저장소를 받는다(공개 방식은 아래 "정할 것").
2. `docker compose up -d` → 브라우저에서 `http://localhost:8501`
3. 첫 화면에서 Gemini 키를 붙여넣고 저장한다.
4. 프로필 탭에서 이력서로 프로필 채우기 → 저장 → 공고 탭에서 수집 → 평가.
5. 끌 때 `docker compose down`. 다시 켜도 키·프로필·공고·점수가 남아 있다.

## 기능 요구사항

### Docker

| ID | 내용 |
| --- | --- |
| F1 | `Dockerfile`: 앱 이미지. `requirements.txt` + `requirements-ocr.txt` 설치, OCR 한국어 모델 파일을 빌드 때 미리 받아 넣는다(첫 OCR 때 내려받지 않음). Streamlit을 8501에서 띄운다 |
| F2 | `docker-compose.yml`: `app`(JOBVIS) + `db`(Postgres) 두 서비스. 앱은 DB가 준비된 뒤 뜬다. 포트는 `127.0.0.1:8501`에만 연다(같은 와이파이의 다른 PC에서 못 들어옴) |
| F3 | 볼륨으로 DB 데이터, `data/`(공고 원문·받은함), 프로필, 화면에서 넣은 키를 남긴다. `docker compose down` 뒤 다시 올려도 유지된다. 지우려면 `docker compose down -v` |
| F11 | `.env`·`service_account.json`·`profile.yaml`·`data/`는 이미지에 넣지 않는다(`.dockerignore`) |

### 키

| ID | 내용 |
| --- | --- |
| F4 | LLM 키가 없으면 화면 맨 위에 키 입력 칸을 띄운다: 발급 주소 링크, 붙여넣기 칸(가림), 저장 버튼. 저장하면 볼륨 안 설정 파일에 쓰고 바로 쓴다. 키가 있으면 "키 바꾸기"로만 연다 |
| F5 | 키는 화면·로그·오류 문구에 다시 보이지 않는다(끝 4자리만 표시 가능). 키가 틀리면 지금의 키 오류 안내를 그대로 보여준다 |
| F12 | Docker 실행의 기본 모델은 새로 받은 무료 키에서 되는 `google_genai:gemini-flash-lite-latest`로 한다(`.env.example`과 같게) |

### 저장

| ID | 내용 |
| --- | --- |
| F6 | 저장 방식을 설정(`JOBVIS_STORAGE`)으로 고른다: `db`(기본, Docker) 또는 `sheet`(지금 방식). 수집·평가·화면·받은함·스킬 갭이 두 방식 모두에서 같은 결과를 낸다 |
| F7 | DB에는 지금 시트 열과 같은 내용을 저장한다: 수집 정보, 평가 결과, 평가 체크, 관심없음, 지원 표시. 같은 공고 중복 저장 막기도 같다 |
| F8 | DB 표는 처음 실행 때 자동으로 만든다. 사용자가 SQL을 실행할 필요 없다 |
| F9 | 시트 방식 사용자가 바꾸지 않으면 동작이 지금과 같다(`.env`에 `JOBVIS_STORAGE`가 없고 시트 설정이 있으면 `sheet`) |

### OCR

| ID | 내용 |
| --- | --- |
| F10 | `JOBVIS_OCR=off`면 OCR을 쓰지 않고 지금 "OCR 미설치"일 때처럼 동작한다. Mac 등 OCR이 안 도는 PC의 대비책 |

### 안내

| ID | 내용 |
| --- | --- |
| F13 | README에 "반 사람용 시작하기"(위 사용 흐름 5단계), 데이터가 남는 곳과 지우는 법, "Mac은 아직 확인 안 함", 개인 사용 원칙(수집한 공고를 공유·공개하지 않음)을 적는다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 테스트는 DB 서버·Docker 없이 돈다. DB 저장은 메모리 DB 등 가짜로 검증한다 |
| N2 | 새 의존성: Postgres 연결 라이브러리(설계에서 고름). 사전 승인 대상이라 설계 PR에서 확정한다 |
| N3 | CI에 `docker build`가 되는지 확인을 더한다(이미지를 올리지는 않음) |
| N4 | 개인정보(프로필, 이력서에서 뽑은 내용, 공고 원문, 점수)는 각자 PC의 볼륨에만 있다. 평가 때 Gemini로 보내는 것은 지금과 같다 |
| N5 | 이미지 크기, 첫 실행 시간, OCR 메모리 사용량을 `03-test.md`에 실측해 적는다 |

## 하지 않는 것

- 웹 공개, 공유 서버, 로그인, 여러 사용자 분리 (사용자 결정: 최후순위)
- 내 Gemini 키를 나눠 쓰기. 각자 PC에 키가 깔려 숨길 수 없음
- Mac(Apple Silicon)용 이미지
- 기존 시트 데이터를 DB로 옮기는 기능 (필요하면 다음 버전 후보)
- 미리 빌드한 이미지를 레지스트리에 올리기 (저장소 공개 방식이 정해진 뒤)

## 정할 것

- 반 사람이 코드를 받는 방법: 저장소 public 전환을 앞당기기 / collaborator 초대 / 이미지만 공개. 추천은 public 전환(전환 전 커밋 이력 비밀 검사). 정해지기 전에는 각자 받은 코드로 `docker compose up --build`
- Linux 이미지에서 `paddleocr==3.7.0`, `paddlepaddle==3.3.1` 고정 버전이 그대로 설치되는지는 설계 단계에서 확인
