# v0.6 회고

2026-10-22 작성. v0.6 요구사항 #39, 설계 #40, 구현 #41.

## 바뀐 결정

- 저장소 기본값: 처음엔 공유 서버(로그인·사용자별 데이터)까지 생각했음. 재리 결정(각자 키, 각자 PC 보관, 쉬운 설치, 웹은 맨 뒤)으로 Docker compose 각자 실행 + compose 안 Postgres로 좁힘.
- 키 입력: `.env` 편집 대신 화면 첫 칸에서 넣고 `data/settings.env`에 남김. 반 사람이 파일을 안 고쳐도 되게.
- OCR: 재리 요청으로 이미지에 기본 포함(약 2.2GB). 뒤에 크기 부담이 보여 v0.6.2에서 기본·OCR 이미지로 나누기로 바꿈.
- Mac(arm64)은 뺌. `JOBVIS_OCR=off`를 대비책으로 둠.
- 시작 파일은 처음엔 필요 없다고 봄(반 사람 모두 Docker 실습 중). 재리가 실행 파일(.exe)로 시작하기와 설정 시간을 물어 v0.6.2에서 `.bat` + 미리 만든 이미지로 다시 넣음.

## 배운 점

- `store`가 `JOBVIS_STORAGE`로 시트·DB를 고르게 하니 수집·평가·화면 코드를 거의 안 고침. DB 표를 시트 열과 같게 둔 덕분.
- 테스트는 SQLite로 DB 방식을 돌림. Postgres만의 동작은 compose 실측과 Docker CI로 확인함.
- Docker의 이점은 "빠름"이 아니라 "덜 깨짐"(Windows의 Python·paddle·shapely 설치 문제, 시트 설정이 없어짐). 시간 이점은 미리 만든 이미지가 있어야 생김.
- 이 작업 환경은 deb.debian.org·huggingface가 막혀 OCR 모델 받기를 직접 못 확인함. Docker CI에 맡김.
- slim 이미지의 paddle은 `libgomp1`·`libgl1`이 있어야 뜸.
