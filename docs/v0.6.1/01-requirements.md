# v0.6.1 요구사항

2026-10-22 초안(사용자 확인 전). v0.6 반 배포를 더 쉽게 한다. 반 사람이 시작 파일을 더블클릭하면 미리 만든 이미지를 받아 화면이 열리고, OCR은 원하는 사람만 따로 받는다.

## 목표

1. 반 사람이 `git clone`과 이미지 빌드(약 5–10분) 없이 시작 파일 더블클릭으로 화면을 연다.
2. 처음 받는 이미지를 줄인다. OCR은 고른 사람만 더 받는다.
3. 흐름: 시작 파일 → (첫 화면) 키 입력 → 웹 화면.

## 사용자 결정 (2026-10-22)

- ".exe 파일 만들어서 시작하는 것도 되나 ?" / "실행파일 -> 키 입력 -> 웹화면"
- "OCR 모델 다운하기[0GB] 이런식으로 빼는건 어떤지 ?" → OCR을 기본에서 빼고 크기를 보여주며 고르게 함
- 위 두 가지에 대한 제안(시작 파일은 `.bat` 먼저, 키는 웹 첫 화면 유지, 미리 만든 이미지, 기본·OCR 이미지 둘로 나눔)에 "진행"

## 사용 흐름 (반 사람 기준)

1. 시작 파일 묶음(시작 파일 + compose 파일)을 받아 폴더에 푼다(받는 곳은 아래 "정할 것").
2. Docker Desktop을 켜고 `JOBVIS 시작.bat`을 더블클릭한다.
3. 처음 한 번 "OCR도 받을까요? (약 N GB 더)"에 답한다. 답은 기억한다.
4. 이미지를 받고 앱이 뜨면 브라우저가 `http://localhost:8501`로 열린다.
5. 첫 화면에서 Gemini 키를 넣고 쓴다(v0.6과 같음).
6. 끌 때 `JOBVIS 끄기.bat`. 다시 켜도 키·프로필·공고·점수가 남는다.

## 바뀌는 결정

| 결정 | v0.6 | v0.6.1 |
| --- | --- | --- |
| 시작 방법 | `git clone` → `docker compose up -d`(빌드) | 시작 파일 더블클릭, 미리 만든 이미지 받기. 기존 방법도 됨 (F1–F4) |
| OCR | 이미지에 기본 포함 | 기본 이미지에서 뺌. 시작 파일에서 OCR 포함 이미지를 고름 (F5–F8) |
| 이미지 배포 | 레지스트리에 올리지 않음 | GitHub 패키지(GHCR)에 기본·OCR 두 이미지를 올림 (F9) |

## 기능 요구사항

### 시작 파일

| ID | 내용 |
| --- | --- |
| F1 | `JOBVIS 시작.bat`(Windows): Docker가 없거나 꺼져 있으면 "Docker Desktop을 켠 뒤 다시 실행하세요"를 보여주고 멈춘다 |
| F2 | 이미지를 받고(`pull`) 앱과 DB를 띄운 뒤, 앱이 준비되면 브라우저로 `http://localhost:8501`을 연다. 진행 중에는 지금 무엇을 하는지 한국어로 보여준다 |
| F3 | `JOBVIS 끄기.bat`: 앱과 DB를 끈다. 데이터는 남긴다 |
| F4 | 실패하면(받기 실패, 포트 8501 사용 중 등) 원인과 할 일을 한국어로 보여주고 창을 바로 닫지 않는다. 키는 출력하지 않는다 |

### OCR 고르기

| ID | 내용 |
| --- | --- |
| F5 | 처음 실행 때 OCR 포함 여부를 묻는다. 질문에 더 받는 크기(실측값)를 적는다. 답은 시작 파일 옆 설정 파일에 남기고 다음부터 묻지 않는다 |
| F6 | 나중에 바꿀 수 있다(예: `JOBVIS 시작.bat`에서 다시 묻는 방법, 또는 설정 파일 수정). 바꿔도 키·프로필·공고·점수는 남는다 |
| F7 | 기본 이미지에서는 지금 "OCR 미설치"일 때처럼 동작한다. 이미지가 필요한 공고 안내와 받은함 끌어다 놓기 칸에 "OCR을 쓰려면 시작 파일에서 OCR 포함을 고르세요(약 N GB)"를 보여준다 |
| F8 | OCR 포함 이미지는 v0.6과 같다(OCR 라이브러리 + 한국어 모델을 미리 넣음) |

### 이미지

| ID | 내용 |
| --- | --- |
| F9 | GitHub Actions가 main에 머지될 때 기본·OCR 두 이미지를 만들어 GHCR에 올린다. 태그는 버전과 `latest` |
| F10 | 저장소를 받아 `docker compose up -d --build`로 직접 빌드하는 방법(v0.6)도 그대로 된다. 파이썬으로 직접 실행하는 방법과 시트 방식도 그대로 된다 |
| F11 | README "반 사람용 시작하기"를 시작 파일 기준으로 고치고, 직접 빌드하는 방법은 아래로 옮긴다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 테스트는 Docker 없이 돈다. 화면 안내 문구(F7)는 pytest로 확인한다. `.bat`은 pytest로 확인할 수 없어 Windows에서 손으로 확인하고 `03-test.md`에 적는다(못 하면 "미확인") |
| N2 | 기본 이미지와 OCR 이미지의 크기(받는 크기·풀린 크기)를 실측해 `03-test.md`와 F5 질문 문구에 적는다 |
| N3 | Docker CI는 두 이미지가 모두 빌드되고 뜨는지 확인한다. 기본 이미지에는 OCR 라이브러리가 없어야 한다 |
| N4 | 공개로 올리는 이미지에는 키·`.env`·`service_account.json`·개인 데이터가 없어야 한다(v0.6 F11 유지). 올리기 전 CI에서 이미지 안에 그런 파일이 없는지 확인한다 |

## 하지 않는 것

- `.exe` 실행파일. 서명 없는 exe는 Windows 보안 경고·백신에 잘 걸린다. `.bat`을 먼저 써 보고 필요하면 다음 버전 후보로 둔다
- 시작 파일에서 키 입력. v0.6의 웹 첫 화면 키 입력을 그대로 쓴다
- 화면 버튼으로 실행 중에 OCR 라이브러리 설치. 느리고 깨지기 쉬워서 이미지를 고르는 방식으로 한다
- Mac(Apple Silicon)용 시작 파일·이미지

## 정할 것

- 반 사람이 시작 파일 묶음과 이미지를 받는 방법. 이미지는 GHCR 패키지를 공개로 바꾸면 로그인 없이 받는다(저장소가 private이어도 패키지만 공개할 수 있는지는 설계에서 확인). 시작 파일 묶음은 저장소 public 전환 후 Releases에 올리기(추천, 전환 전 커밋 이력 비밀 검사) 또는 반 채팅방에 zip으로 나누기
- 기본 이미지가 실제로 얼마나 줄어드는지(설계 때 시험 빌드로 확인). 거의 안 줄면 OCR 분리(F5–F8)는 빼고 시작 파일만 한다
