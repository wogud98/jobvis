# v0.6.1 회고

2026-10-22 작성. 화면 다듬기 F1–F10·F15–F25, 키 보안 F11–F14. PR #42–#46.

## 바뀐 결정

- 처음 v0.6.1은 시작 파일·OCR 분리였음. 재리 PC 화면 피드백이 먼저 쌓여 v0.6.1을 화면 다듬기로 바꾸고 시작 파일은 v0.6.2로 옮김.
- 키 칸: 화면 맨 위 카드(F2) → 제목 옆 "🔑 키" 버튼과 창(F17). 카드가 크고 제목과 붙어 보였음.
- 결과 안내: 결과 칸·자세히 토글 → 알림(toast) 한 번, 문제 있을 때만 빨간 칸(F5).
- 고른 요약 칸 표시: 초록 테두리 → 굵은 테두리·✓(F15) → 색 뒤집기(F21). 초록이 다른 곳에도 쓰여 구분이 안 됐음.
- 어두운 테마 색: 재리가 고른 색(PR #37)을 회청색 한 계열로 다시 맞춤(F22). 버튼 주 색도 청록 → 초록.
- TOP 5 차트: `st.bar_chart` → 확대·끌기 없는 vega-lite 명세(F23).
- 테마: 서버가 `st.context.theme`으로 색을 고름 → 브라우저가 CSS `light-dark()`로 고름(F25). 테마를 바꿔도 F5가 필요 없음.
- 🔄 새로고침: 공고만 다시 읽음 → 프로필도 저장된 값으로(F24). 확인 창 문구("새로고침하면 저장된 값")와 동작이 달랐음.
- 키 삭제는 이 PC에서만 지움. Google의 키 파기는 하지 않음(재리 확인).

## 배운 점

- 화면 문구가 약속한 동작은 테스트로 묶어야 함. F24는 문구와 코드가 어긋난 채 두 버전을 지남.
- Streamlit 기본 차트는 늘 `.interactive()`라 고정하려면 명세를 직접 써야 함. 새 의존성은 필요 없었음.
- 서버에서 테마를 고르면 테마를 바꾼 뒤 다시 그릴 때까지 색이 어긋남. Streamlit이 앱 칸에 `color-scheme`을 정해 주므로 CSS만으로 풀림.
- 글자색과 테두리색을 한 변수(`ink`)로 쓰면 어두운 테마에서 테두리를 차분하게 할 때 글자도 흐려짐. 역할별로 나눠야 함.
- 이 작업 환경에서 `pkill -f streamlit`은 자기 셸까지 죽임. `ps | awk`로 pid를 골라 끔.
- 평가 후 화면이 갱신되지 않는 문제(F16)는 재현하지 못함. 놓칠 수 있는 길만 막음.

## 다음 버전으로

- v0.6.2 설계: 기본 이미지 크기 실측(OCR 분리가 실제로 줄이는지), GHCR 공개 범위, 시작 파일 묶음 배포 방법.
- 평가 후 갱신 문제가 다시 나면 저장 방식(시트/DB)·건수·탭 확인.
- `light-dark()`가 반 사람 브라우저(Chrome·Edge 123 이상)에서 도는지 확인.
