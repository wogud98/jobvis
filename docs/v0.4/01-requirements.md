# v0.4 요구사항

2026-10-20 확정.

## 목표

사람인 API가 개인에게 발급되지 않아, 공고 출처를 사람인·잡코리아 공개 페이지 크롤링으로 바꾼다. 수집 단계에서 상세 본문까지 가져와 평가가 제목이 아니라 본문을 보고 점수를 매기게 한다.

1. 수집: 사람인·잡코리아 검색 결과에서 공고를 고르고, 새 공고만 상세 본문을 가져온다. 본문 속 이미지는 내 PC에서 도는 무료 OCR로 글자를 읽는다. 원문은 PC에만 두고, 시트에는 기본 정보를 저장한다. LLM을 부르지 않는다.
2. 평가: v0.3 그대로. 다만 공고 제목 대신 저장해 둔 본문을 LLM에 넘겨 요약과 점수를 함께 받는다.

근거: 2026-10-20 PC에서 시험함(저장소 밖 `C:\dev\jobvis-spike`). 검색 결과 사이트당 5건, 상세 본문 4건, 이미지 공고 1건(이미지 10장) OCR 비교.

## 실행 방법

| 명령 | 하는 일 |
| --- | --- |
| `python main.py --keyword 백엔드 ...` | 두 사이트에서 수집만 |
| `python main.py --keyword 백엔드 --source saramin` | 한 사이트만 수집 (`saramin`, `jobkorea`, 생략하면 둘 다) |
| `python main.py --score`, `--score all`, `--gaps` | v0.3과 같음 |

## 기능 요구사항

### 목록 수집

| ID | 내용 |
| --- | --- |
| F1 | 사람인 API 호출을 없애고 사람인 검색 결과 페이지(`/zf_user/search/recruit`)와 잡코리아 검색 결과 페이지(`/Search/`)에서 공고를 읽는다 |
| F2 | 실행 옵션 `--source`로 사이트를 고른다. 값은 `saramin`, `jobkorea`이고 생략하면 둘 다 수집한다 |
| F3 | v0.2의 조건 입력(`--keyword`, `--location`, `--job`, `--career`, `--count`)을 그대로 받는다. 사이트 검색 주소에 넣을 수 있는 조건은 주소에 넣고, 넣을 수 없는 조건은 받은 목록에서 프로그램이 거른다 |
| F4 | 목록에서 출처, 공고ID, 회사, 제목, 경력, 학력, 지역, 마감일, 링크를 읽는다. 목록에 없는 칸은 비운다 (잡코리아 학력 등) |
| F5 | 마감일은 `YYYY-MM-DD`로 바꿔 저장한다. 사람인 "~ 11/12(목)"처럼 연도가 없으면 오늘 이후 가장 가까운 날짜로 본다. 상시 채용은 "상시"로 저장한다 |
| F6 | 잡코리아 광고 카드는 저장하지 않는다 |
| F7 | `--count`는 사이트당 개수다. 기본 10, 최대 30. 검색 결과는 사이트당 1페이지만 읽는다 |

### 중복 방지

| ID | 내용 |
| --- | --- |
| F8 | 출처+공고ID가 시트에 이미 있으면 상세 본문을 가져오지 않고 건너뛴다 |
| F9 | 다른 사이트에 같은 공고가 있으면(회사명과 제목에서 공백·기호를 뺀 값이 같으면) 먼저 저장된 것만 남기고 건너뛴다 |

### 상세 본문

| ID | 내용 |
| --- | --- |
| F10 | 새 공고만 상세 본문을 가져온다. 사람인은 본문만 담긴 주소(`/zf_user/jobs/relay/view-detail?rec_idx=공고ID`), 잡코리아는 본문 창 주소(`/Recruit/GI_Read_Comt_Ifrm?Gno=공고ID`)를 공고당 한 번 요청한다 |
| F11 | 본문에서 글자만 뽑는다. 스크립트, 스타일, 숨은 요소는 버린다 |
| F12 | 본문 속 이미지는 OCR로 글자를 읽어 본문 뒤에 붙인다. 가로나 세로가 300px보다 작은 이미지는 건너뛰고, 공고당 최대 10장만 읽는다 |
| F13 | OCR은 PaddleOCR을 쓴다. 설치돼 있지 않으면 이미지를 건너뛰고 글자 본문만 저장하며, 설치 방법을 한 번 출력한다 |
| F14 | 원문(글자 본문 + OCR 결과)은 PC의 `data/postings/{출처}_{공고ID}.txt`에 저장한다. 시트에는 원문을 넣지 않는다 |
| F15 | 시트에 "출처"와 "본문" 열을 추가한다. "본문" 열에는 상태를 적는다: 글자, 글자+이미지, 이미지 일부 못 읽음, 본문 미확보 |
| F15a | 글자 본문과 OCR 결과를 합쳐 200자 미만이면 "본문 미확보"로 표시한다. robots 금지로 이미지를 받지 못한 경우가 대부분이다 |

### 평가 (v0.3 변경)

| ID | 내용 |
| --- | --- |
| F16 | v0.3 평가(F5–F16)를 그대로 쓰되, LLM에 공고 제목·경력·학력·키워드 대신 저장된 원문을 넘긴다. 원문이 6,000자를 넘으면 앞에서부터 6,000자만 넘긴다 |

| F18 | 평가 호출에서 받는 요약을 늘린다: 주요업무, 자격요건, 우대사항, 기술스택을 각각 한 줄로 받아 시트에 저장한다 |

## 하지 않는 것

- 사람인 API. 개인에게 발급되지 않음. 나중에 키를 받으면 다시 붙일 수 있게 출처 모듈 형태만 맞춘다
- 검색 결과 2페이지 이후, 하루 여러 번 자동 실행 (메일 발송 버전에서 다시 봄)
- 공고 본문 검사(프롬프트 인젝션 표시, 로드맵 후보 3). v0.4는 숨은 요소를 버리는 것(F11)까지만 하고 표시는 다음 버전 후보로 둔다
- AI 비전 모델로 이미지 읽기 (비용)
- robots 금지 이미지를 받기 위한 우회(브라우저인 척하는 User-Agent, 브라우저 자동화). 2026-10-20 결정
- 사용자가 직접 이미지를 가져오게 돕는 기능(예: 공고를 보는 중 북마크 버튼으로 화면의 이미지를 JOBVIS에 넘겨 OCR). 사용자가 원하면 붙이는 다음 버전 후보로 둔다. robots와 부딪히지 않는 방식인지 그 버전 설계에서 따진다
- 잡플래닛 등 다른 사이트

## 알려진 한계

- 화면 클래스 이름에 기대어 읽으므로 사이트가 개편되면 깨진다. 잡코리아가 더 깨지기 쉽다
- 사람인·잡코리아에 직접 올린 공고 이미지(`pds.saramin.co.kr`, `saraminimage.co.kr`, `file1.jobkorea.co.kr`)는 robots 전면 금지라 자동으로 받지 못한다. 회사 서버에 올린 이미지만 읽는다. 2026-10-20 시험에서 이미지 16장 중 10장이 금지였다. OCR은 유지한다(2026-10-20 사용자 결정)
- OCR은 2단 배치에서 줄 순서가 섞이고 띄어쓰기가 붙는다. 평가 단계 LLM이 정리한다
- PaddleOCR은 CPU에서 큰 이미지 한 장에 30초 남짓 걸린다. 윈도우에서는 가속 옵션(mkldnn)을 꺼야 돈다
- 약관상 동의 없는 복제·제3자 제공·영리 이용이 금지돼 있다. 개인 사용 범위를 넘으면 안 된다

## 확정한 것

2026-10-20 사용자와 대화에서 정함.

- 사람인 API가 개인에게 발급되지 않아 사람인·잡코리아 공개 페이지 크롤링으로 바꾼다
- 상세 본문까지 수집하고, 본문 정리는 2단계 평가에서 한다
- 이미지는 AI 비전 대신 무료 로컬 OCR(PaddleOCR)로 읽는다. 이미지 서버 대부분이 robots 금지여도 OCR은 유지한다
- robots 금지 이미지는 우회하지 않고 "본문 미확보"로 둔다. 사용자가 원하면 직접 가져오게 돕는 기능은 이후에

## 확인할 것

- 두 사이트 검색 주소에 지역·직무·경력 조건을 넣는 방법. 사람인 검색이 API와 같은 지역 코드(`loc_mcd`)를 받는지 (설계 단계)
- 잡코리아 검색을 최신순으로 정렬할 수 있는지. 관련도순 상위에 무관한 공고가 섞임 (설계 단계)
- 잡코리아 학력 숫자 코드(`educationCode`)의 뜻. 모르면 비워 둔다
- 시트 "출처" 열이 없는 기존 줄은 출처를 사람인으로 볼지
