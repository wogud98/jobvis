# v0.5.2 요구사항

2026-10-21 확정. 화면에서 다 하기: 수집·평가·받은함을 화면 버튼으로 실행하고, 이력서·포트폴리오 파일에서 프로필을 자동으로 채운다.

## 목표

1. 터미널을 열지 않고 화면 하나로 수집 → 평가 → 결과 보기까지 한다.
2. 프로필을 처음부터 적지 않고, 이미 써 둔 이력서·포트폴리오 파일을 올려 채운 뒤 고쳐서 저장한다.

## 사용자 요청 (2026-10-21)

- "프로필을 자기가 써 놓은 이력서나 포트폴리오(사람마다 다르겠지?)에서 읽고 자동으로 입력해 주는 기능도 구현이 가능한가?"
- 사용법 첫 줄 "터미널에서 `python main.py --keyword 백엔드`로 공고를 모으고 `--score`로 평가합니다"를 보고: "이 과정도 이 페이지에서 할 수 있도록 수정하자"

## 기능 요구사항

### 수집 (공고 탭)

| ID | 내용 |
| --- | --- |
| F1 | 공고 탭 위쪽에 "수집" 카드를 둔다. 입력: 키워드(필수), 지역, 직무, 경력(전체·신입·경력), 사이트(사람인·잡코리아, 기본 둘 다), 사이트당 개수(1–30, 기본 10). 터미널 `--keyword`, `--location`, `--job`, `--career`, `--source`, `--count`와 같은 뜻 |
| F2 | 지역과 직무는 입력할 때 추천 검색어가 뜨고 골라 넣는다. 목록은 `agent/codes.py`의 지역·직무 이름. 목록에 없는 직무는 직접 입력할 수 있다(터미널처럼 비슷한 이름을 찾아 줌) |
| F3 | 키워드도 추천 검색어를 보인다. 목록은 직무 이름과 프로필의 희망 직무·주력 기술. 목록에 없는 키워드는 직접 입력한다 |
| F4 | "수집" 버튼은 터미널과 같은 수집 그래프를 실행한다. robots.txt, 요청 간격 3초, 403·429 멈춤 등 v0.4 규칙은 그대로 |
| F5 | 실행 중에는 진행 상황(사이트, 처리한 공고 수 / 전체)을 보이고, 끝나면 터미널 출력과 같은 결과 요약(사이트별 저장·건너뜀·실패, 본문 미확보 수, 본문 채움)을 보인다 |
| F6 | 끝나면 시트를 다시 읽어 카드·요약 칸을 새로 그린다 |

### 평가 (공고 탭)

| ID | 내용 |
| --- | --- |
| F7 | "평가" 버튼과 대상 고르기: 체크한 공고(`--score`), 점수 없는 공고 전부(`--score all`). 대상 수를 버튼 옆에 미리 보인다 |
| F8 | 저장된 `profile.yaml`로 평가한다. 없거나 필수 칸이 틀리면 실행하지 않고 프로필 탭으로 안내한다 (v0.5 F13, F16과 같은 검사) |
| F9 | 실행 중 진행 상황(처리한 공고 수 / 대상 수), 끝나면 평가 대상·완료·제외·건너뜀·실패 수를 보이고 시트를 다시 읽는다 |

### 받은함 (공고 탭)

| ID | 내용 |
| --- | --- |
| F10 | `data/inbox/`에 이미지가 있으면 "받은함 읽기" 버튼과 이미지 수를 보인다. 누르면 `--inbox`와 같이 실행하고 결과(읽은 장 수, 본문 채움, 건너뜀과 이유)를 보인다 |
| F11 | OCR이 설치돼 있지 않으면 버튼 대신 설치 안내를 보인다 (v0.5 F44) |

### 실행 공통

| ID | 내용 |
| --- | --- |
| F12 | 수집·평가·받은함은 한 번에 하나만 실행한다. 실행 중에는 세 버튼을 모두 잠근다. 같은 PC에서 화면 창을 두 개 열어도 겹쳐 실행되지 않는다 |
| F13 | 실행 중 오류(인증 파일 없음, 시트 없음, 네트워크, LLM 오류)는 v0.5 F9처럼 이유와 확인할 것만 보이고 키·경로는 보이지 않는다. 화면은 꺼지지 않는다 |
| F14 | 터미널 명령은 그대로 둔다. 화면과 터미널은 같은 함수를 부른다 |
| F15 | 사용법 토글 내용을 화면 실행 기준으로 바꾼다. 첫 줄: "수집 카드에 키워드를 넣고 수집 → 평가를 누릅니다" |

### 이력서로 프로필 채우기 (프로필 탭)

| ID | 내용 |
| --- | --- |
| F16 | 프로필 탭 위쪽에 "이력서·포트폴리오로 채우기" 칸을 둔다. 파일: PDF(글자가 있는 PDF), Word(.docx), 텍스트(.txt), 마크다운(.md). 한 번에 여러 개(예: 이력서 + 포트폴리오), 파일당 10MB까지 |
| F17 | 파일에서 글자를 뽑아 LLM을 한 번 부르고, 프로필 칸(기술 3칸·자격증, 경력 연수·학력·프로젝트·교육, 희망 직무·지역·하고 싶은 일, 선호 문화)에 맞춘 JSON으로 받는다. 양식이 사람마다 달라도 LLM이 칸을 찾는다. LLM은 `init_chat_model(LLM_MODEL)`로만 만든다 |
| F18 | 받은 값은 저장하지 않고 입력란에만 채운다. 사용자가 확인·수정한 뒤 "저장"을 눌러야 `profile.yaml`에 쓴다 |
| F19 | 기본은 빈 칸만 채운다. 이미 값이 있는 칸은 그대로 두고, 목록 칸은 없는 항목만 더한다. "이미 적은 칸도 바꾸기"를 켜면 받은 값으로 바꾼다 |
| F20 | 채운 칸을 표시한다(예: "이력서에서 채움" 배지). 경력 연수는 LLM이 계산한 값이라 확인하라는 안내를 붙인다 |
| F21 | 글자를 뽑지 못한 파일(스캔 이미지 PDF, 빈 파일, 깨진 파일), 모르는 형식, 10MB 초과는 그 파일만 건너뛰고 이유를 보인다. LLM 응답이 형식에 맞지 않으면 아무 칸도 바꾸지 않고 오류를 보인다 |
| F22 | 글자는 파일들을 합쳐 앞 20,000자까지만 LLM에 보낸다 |

### 테마 색

| ID | 내용 |
| --- | --- |
| F23 | 포인트 컬러를 초록으로 바꾼다(2026-10-21 사용자 요청 "보라색 조금 아쉬운데 초록 계열로", "포인트 컬러가 초록이지 전체를 초록으로 할 필요 없다"). 초록은 버튼·차트·고른 키워드·카드 점수에만 쓴다. 바탕은 흰색·연회색(아래쪽만 아주 옅은 초록), 글자·요약 숫자·판정 배지는 무채색. 신뢰 배지 색(높음 초록, 보통 노랑, 낮음 빨강)은 그대로 |

### 보완 (2026-10-21, PC에서 써 본 뒤)

사용자 의견: 수집 결과 칸이 "log처럼 보인다, 사용자에게 보여줄 필요가 없다". 이력서 PDF와 LLM 오류 문구가 무엇을 해야 할지 알려 주지 않음.

| ID | 내용 |
| --- | --- |
| F24 | 화면 실행 결과는 결과 한 줄(예: "새 공고 17건을 저장했습니다")만 기본으로 보인다. 할 일이 있을 때만 노란 안내, 문제(실패, 수집 멈춤)가 있을 때만 빨간 안내를 더한다. 사이트별 수 등 터미널과 같은 줄은 접힌 "자세히" 안에 둔다. 수집·평가·받은함 모두. 터미널 출력은 그대로 (F5, F9, F10 표시 방식을 바꿈) |
| F25 | 본문 없는 공고 안내는 터미널 명령(`--inbox`) 대신 화면에서 할 일("카드 '자세히'에서 공고 이미지를 넣으면…")로 보인다 |
| F26 | LLM 모델 없음·API 키 틀림·권한 없음·사용 한도 초과는 "터미널 로그를 확인해 주세요" 대신 고칠 방법(예: ".env의 LLM_MODEL을 …로 바꿔 주세요")을 보인다. 이력서 채우기와 평가 실패 모두 |
| F27 | 이력서 PDF·Word를 읽는 라이브러리가 없으면 "pypdf가 설치돼 있지 않음. pip install -r requirements.txt 후 화면을 다시 켜 주세요"를 보인다. `.env.example`의 기본 모델은 `google_genai:gemini-flash-lite-latest`로 바꾼다(`gemini-2.5-flash`는 새로 받은 키에서 404가 날 수 있음) |
| F28 | 화면 스타일을 글래스모피즘에서 네오 브루탈리즘으로 바꾼다(2026-10-21 사용자 요청, 시안 확인 후 "네"). 카드·버튼·입력란·안내 칸에 굵은 검정 테두리와 흐림 없는 검정 그림자, 크림색 단색 바탕, 요약 칸 4개는 노랑·하늘·초록·분홍 단색 면, 제목은 초록 형광펜 밑줄, 배지·키워드는 각진 모양에 검정 테두리. 버튼은 누르면 그림자만큼 눌린다. 포인트 색은 초록(F23) 그대로. v0.5.1 F17–F19의 글래스 카드·그라데이션 배경을 대신한다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 의존성: `pypdf`(PDF 글자 뽑기), `python-docx`(Word 글자 뽑기)를 `requirements.txt`에 넣는다 |
| N2 | 올린 이력서 파일은 디스크에 저장하지 않는다(메모리에서 읽고 버림). 뽑은 글자와 LLM 응답은 로그·오류 메시지에 쓰지 않는다 (v0.5 N2와 같은 이유) |
| N3 | 이력서 글자가 LLM 제공자(기본 Gemini)로 전송된다는 것을 업로드 칸에 적는다 |
| N4 | 화면은 여전히 PC 전용·localhost (v0.5 N4) |
| N5 | 화면 실행 로직(입력 → 실행 옵션, 대상 수 세기, 실행 잠금, 결과 요약 글, 이력서 글자 뽑기, LLM 응답 → 입력란 값 합치기)은 Streamlit 밖 함수로 두고 가짜 사이트·가짜 LLM·가짜 시트로 테스트한다. 키워드 없음, 개수 범위 밖, 실행 중 두 번 누름, 프로필 없음, 시트 오류, OCR 없음, 빈 받은함, 스캔 PDF, 깨진 docx, 형식 틀린 LLM 응답, 빈 칸만 채우기와 덮어쓰기를 포함한다. 실제 API 호출 없음 |

## 하지 않는 것

- 스캔 이미지 PDF의 OCR. 글자 PDF만. 써 보고 필요하면 다음 후보로
- 화면에서 스킬 갭(`--gaps`) 보기. 다음 후보로
- 수집·평가를 화면을 닫아도 계속 돌리는 백그라운드 실행, 예약 실행(매일 아침은 v0.7 메일에서)
- 실행 중 취소 버튼. 끝날 때까지 기다린다(30건 수집은 몇 분)
- 이력서 원본 보관, 여러 프로필
