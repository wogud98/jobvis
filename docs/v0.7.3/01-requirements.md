# v0.7.3 요구사항

2026-10-23 확정(재리 "진행" 06:08). 기술 모아보기를 다듬는다. 수집·평가·점수 계산·저장 칸·메일 내용은 바꾸지 않는다.

## 사용자 의견과 결정

- "기술 모아보기에 언급된 모든 기술도 볼 수 있었으면 한다"(05:59) → 같은 높이 칸 안에서 스크롤로 전부(제안 → "진행")
- "SQL MySQL Agentic AI LLM Agent와 같이 비슷한 키워드는 사실상 1개로 봐서 합쳐야 하는 게 아닌가"(05:59)
- "기본적인 같은 말 사전을 보관하고, 새로이 추가된 단어가 많이 쌓이면 업데이트 하는 방식은?"(06:06) → 저장소의 사전 파일 하나, 개발 쪽이 버전 때 보강
- "SQL MySQL 같은 경우는 현행 유지하자"(06:06) → 계열로 묶지 않고 같은 말만
- 사전에 없는 이름 확인 명령은 "삭제. 사용자에게 너무 많은 걸 요구하면 안 된다"(06:07)
- "사전으로 인해 용량이 너무 커지지는 않을까"(06:07) → 한 줄 50–60바이트, 수십 줄이면 몇 KB. 문제는 크기가 아니라 잘못 묶는 것이라 테스트로 막음
- 수집 후 자동 평가는 "안 할게"(06:11) → 하지 않음

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 기술 모아보기 두 탭(많이 찾는 기술, 내가 부족한 것)은 위 10개가 아니라 전부 보인다. 칸 높이는 그대로(v0.7.2 F11)이고 넘치면 칸 안에서 스크롤. 위 요약 "많이 찾는 기술 N개 중 내 기술 M개"도 전부 기준 |
| F2 | 같은 말 사전: 같은 기술의 다른 이름(예: Agentic AI·AI Agent·LLM Agent → AI 에이전트, k8s → Kubernetes)을 한 기술로 세고 대표 이름으로 보인다. 띄어쓰기·대소문자만 다른 이름은 지금처럼 사전 없이 같게 본다 |
| F3 | "내 기술" 판단(초록 칩)도 같은 말 사전을 쓴다. 프로필에 k8s가 있으면 공고의 Kubernetes는 내 기술. 자세히의 기술 칩도 같은 기준 |
| F4 | 명령줄 `--gaps` 순위도 같은 말 사전으로 합친다(화면과 같은 함수). 보이는 개수는 지금처럼 10개 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 새 의존성 없음. 사전은 `agent/skill_aliases.yaml`(PyYAML은 이미 씀), 사용자가 할 일 없음 |
| N2 | 같은 말만 넣는다. SQL·MySQL, Java·JavaScript처럼 다른 기술은 묶지 않는다. 한 이름이 두 묶음에 들어가면 테스트가 실패한다 |
| N3 | LLM을 부르지 않는다. 이미 평가한 공고도 다시 평가 없이 합쳐져 보인다 |

## 하지 않는 것

- SQL·MySQL처럼 계열로 묶기(재리 결정)
- 사전에 없는 이름 확인 화면·명령(재리 결정)
- LLM으로 이름 정리
- 수집 후 자동 평가(재리 결정)
