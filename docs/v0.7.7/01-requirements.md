# v0.7.7 요구사항

2026-11-06 확정(재리 "진행" 01:03). 긴 공고 이미지를 OCR하다 앱이 강제 종료돼 수집이 1–3건에서 끊기는 일을 막고, 끊겼을 때 화면에 알린다. 저장 칸·평가·수집 개수 규칙은 바꾸지 않는다.

## 사용자 의견과 결정

- "FDE로 30 셋팅하고 공고 수집했는데 3건 밖에 안뜬다 … DB 내용이 없음에도 중복 공고를 걸러낸 느낌"(11-05 07:55), "백엔드 검색하니까 1건 수집함"(08:13)
- 재리 PC 진단(11-05): 목록·조건·중복은 정상(사람인 1쪽 40건, 잡코리아 22건, DB 비우면 사이트당 30건 채움). 본문 단계에서 세로로 긴 이미지(950×6744)를 PaddleOCR이 한 번에 읽다가 메모리 약 7.5GB → WSL 한도 7.67GB 초과로 streamlit 강제 종료. 앱 컨테이너 재시작 5번, 화면에는 오류 없음
- 내 안: 긴 이미지 잘라 읽기 + 해상도 상한, 끊김 알림을 fix PR 하나로 → "진행"

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 세로로 긴 이미지는 일정 높이(1600px) 조각으로 잘라 차례로 OCR한다. 경계 줄이 끊기지 않게 조각끼리 조금(80px) 겹친다 |
| F2 | 가로가 1280px보다 넓은 이미지는 비율대로 줄인 뒤 읽는다 |
| F3 | 겹친 곳에서 두 번 읽힌 줄은 한 번만 남긴다. 빈 줄을 빼는 규칙은 그대로 |
| F4 | 수집·평가·이미지로 다시 평가가 끝나기 전에 앱이 꺼지면, 다시 연 화면 위에 "지난 ○○ 작업(시작 시각)이 끝나지 않고 멈췄습니다"와 메모리 부족 가능성, 저장한 공고는 남아 있다는 안내를 보인다 |
| F5 | F4 알림은 한 번 나온 뒤 표시를 지운다. 정상으로 끝나거나 오류로 끝난 작업은 알리지 않는다. 새 작업을 시작하면 알림은 사라진다 |

## 비기능 요구사항

| ID | 내용 |
