# v0.7.9 요구사항

2026-11-06 초안. 재리 확정 전이라 코드는 아직 쓰지 않는다. OCR이 메모리를 넘겨 앱이 강제 종료되고 수집이 끊기는 일을 막는다. 저장 칸·평가·수집 개수 규칙은 바꾸지 않는다.

## 사용자 의견과 결정

- "공고수집중 Streamlit 오류나오고 페이지가 다시 뜨면서 공소수집이 하나도 되지 않음"(11-06 01:29), "1건에서 올라가질 않으며 아무것도 수집되지 않는다"(01:30)
- v0.7.7 적용 뒤에도 끊김: 첫 수집은 9건 저장 뒤, 두 번째 수집(01:41:57 시작)은 0건 저장으로 강제 종료. 두 번 다 메모리 약 7.5GB
- 내 안: 글자 찾기 모델 교체 + 긴 변 제한, OCR 별도 프로세스 → 요구사항 작성 "진행"(02:11)

## 측정

2026-11-06, 앱과 같은 이미지(`ghcr.io/wogud98/jobvis:ocr`, `sha256:b172372a…`)의 일회용 컨테이너, 메모리 상한 6.5GB. 공고 이미지 15장을 이미지마다 새 프로세스에서 `ocr.read`로 읽음. 조건은 FDE 30건, 백엔드 15건(사이트당), 지역·경력 조건 없음.

| 설정 | 결과 |
| --- | --- |
| 모델 로드만 | 569MB |
| 지금 설정 | 15장 중 6장이 상한 초과. 끝난 9장은 1,913–5,892MB |
| 지금 설정, 면적별 | 860×303 1.9GB, 860×572 3.2GB, 1280×566 4.4GB, 860×982 5.1GB, 860×1185 5.9GB, 860×1582 상한 초과 |

- 메모리는 조각 면적에 따라 커짐(1MP당 약 5GB). v0.7.7 조각은 최대 1280×1600(약 2MP)이라 조각으로 나눠도 한도를 넘음
- 조각을 여러 개 읽어도 최대치는 거의 그대로라 쌓이는 문제로 보이지 않음

상한을 넘은 3장을 다른 설정으로 비교함. 기본 설정은 끝나지 않아 글자 수를 비교할 수 없음.

| --- | --- | --- |
| 1920×9964 (사람인 55343779) | 975MB, 36.7초, 3,020자 | 4,612MB, 67.5초, 3,014자 |
| 1920×9964 (사람인 55343953) | 974MB, 38.0초, 3,027자 | 4,622MB, 69.2초, 3,025자 |

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 글자 찾기 모델을 `PP-OCRv5_mobile_det`로 바꾼다. 글자 읽기 모델(`korean_PP-OCRv5_mobile_rec`)은 그대로 |
| F2 | 글자 찾기 전에 이미지 긴 변을 960px 이하로 줄인다(`text_det_limit_type="max"`, `text_det_limit_side_len=960`) |
| F3 | OCR을 앱과 다른 프로세스에서 돌린다. OCR 프로세스가 죽어도 앱과 진행 중인 수집은 멈추지 않는다 |
| F4 | OCR 프로세스가 죽거나 정해진 시간 안에 끝나지 않으면 그 이미지만 못 읽은 것으로 처리하고 다음 이미지로 넘어간다. 공고는 지금의 OCR 실패 때처럼 저장하고 실패 목록에 남긴다 |
| F5 | 수집과 "이미지로 다시 평가" 모두 같은 방식으로 OCR한다 |
| F6 | v0.7.7의 조각 읽기(F1–F3)와 끊긴 작업 알림(F4, F5)은 그대로 둔다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 위 측정의 15장을 메모리 상한 6.5GB 일회용 컨테이너에서 새 설정으로 읽어 모두 끝나고, 이미지 한 장의 최대 메모리가 1.5GB 이하 |
| N2 | 지금 설정으로 끝나는 9장을 새 설정으로 읽어 글자 수와 내용 표본을 비교하고 `03-test.md`에 남긴다 |
| N3 | 새 패키지 없음. 새 모델은 OCR 이미지에 미리 넣어 첫 OCR 때 내려받지 않는다 |
| N4 | 테스트는 PaddleOCR 없이 가짜 모델·가짜 프로세스로 돌린다. OCR 프로세스가 죽는 경우와 시간을 넘긴 경우를 포함한다 |
| N5 | 재리 PC의 Docker 앱에서 수집을 끝까지 한 번 돌려 앱 재시작이 없는지 확인한다. 못 하면 `03-test.md`에 "미확인"으로 쓴다 |

## 하지 않는 것

- Docker·WSL 메모리 한도 바꾸기(v0.7.7과 같은 이유)
- 수집 개수·중복·저장 칸 규칙 바꾸기
- 끊긴 수집을 자동으로 이어 하기
- 설정 화면에 OCR 모델 고르는 칸 넣기

## 설계에서 정할 것

- OCR 프로세스를 이미지마다 띄울지, 하나를 계속 쓰고 죽으면 다시 띄울지(모델 로드 2–8초)
- 시간 상한 값(측정에서 가장 오래 걸린 이미지는 38초)
- 메모리가 넘칠 때 Linux가 앱이 아니라 OCR 프로세스를 죽이는지. 측정에서는 앱과 분리된 컨테이너 상한으로만 확인해 같은 컨테이너 안 동작은 미확인
