# v0.7.6 요구사항

2026-10-27 확정(재리 "진행" 08:47). 같은 조건으로 여러 번 수집해도 이미 저장한 공고가 개수를 채워 새 공고가 안 들어오는 일을 줄인다. 저장 칸·평가·화면은 바꾸지 않는다.

## 사용자 의견과 결정

- "공고 최대 30개인데, 30개씩 여러 개 하면 중복된 공고가 누적되어 신규 공고가 안 들어오는 상황은 없나?"(08:09) → 확인: 검색 결과 첫 쪽만 읽고 앞에서 개수만큼 자른 뒤 중복을 뺐음. 빠진 만큼 채우지 않아 "새 공고 0건"이 될 수 있었음
- 내 안: 중복을 먼저 빼고 개수를 채우고, 모자라면 다음 쪽을 최대 몇 장까지(요청 간격·robots 그대로) → "진행"

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 사이트마다 시트·DB에 이미 있는 공고(출처+공고ID, 또는 회사+제목)는 개수에 넣지 않는다. 본문 미확보 줄을 채울 공고는 지금처럼 새 공고로 다룬다 |
| F2 | 새 공고가 개수보다 모자라면 검색 결과 다음 쪽을 읽는다. 사이트당 최대 3쪽 |
| F3 | 다음 쪽이 비었거나 앞 쪽과 같은 공고만 오면 멈춘다. 개수를 채우면 더 읽지 않는다 |
| F4 | 결과의 "가져옴"은 새 공고 + 이미 있어 건너뛴 공고. 건너뜀 수는 지금처럼 보인다 |
| F5 | 다음 쪽에서 오류가 나면 앞 쪽에서 모은 공고는 그대로 저장하고 실패 목록에 "목록"으로 남긴다. 다음 쪽이 robots 금지면 우회하지 않고 조용히 멈춘다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 요청 간격·robots 확인은 `crawler.py` 그대로(쪽마다 같은 규칙) |
| N2 | 새 의존성 없음. 사이트당 최대 개수 30, 화면·명령줄 옵션 그대로 |

## 하지 않는 것

- 쪽 수를 사용자가 고르는 옵션(사용자에게 많이 요구하지 않음)
- 3쪽보다 깊이 읽기(요청 수가 늘어 차단 위험)
