# v0.3 요구사항 (초안)

## 목표

내 프로필과 공고를 비교해 적합도 점수, 강점, 부족한 점을 시트에 저장한다. 저장된 공고들의 부족한 점을 모아 내가 무엇을 공부해야 하는지 보여준다.

참고: [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)(MIT)의 적합도 기준(`04-job-evaluation.md`)과 스킬 갭 분석(`/upskill`). [로드맵 후보](../roadmap.md#다음-버전-후보) 1, 2.

## 기능 요구사항

### 적합도 채점

| ID | 내용 |
| --- | --- |
| F1 | 내 프로필을 마크다운 파일로 받는다. 실행 옵션 `--profile`로 경로를 지정하고, 생략하면 `profile.md`를 쓴다. 형식 예시는 `profile.example.md`로 저장소에 둔다 |
| F2 | 프로필 파일이 없거나 비어 있으면 사람인 API를 부르기 전에 멈추고, 파일 경로와 예시 파일 이름을 출력한다 |
| F3 | 공고 한 건마다 LLM을 한 번 불러 아래를 함께 받는다: 자격요건 한 줄 요약, 항목별 점수 3개, 강점(최대 3개), 부족한 점(최대 3개). v0.2의 요약 호출을 이 호출로 바꾼다 |
| F4 | 채점 항목은 기술, 경력, 커리어 방향 세 가지이고 각각 0–100 정수다. 항목별 점수 기준표는 프롬프트에 넣는다 (아래 "점수 기준") |
| F5 | 종합 점수는 프로그램이 계산한다. 기술 40%, 경력 30%, 커리어 방향 30% 가중 평균을 반올림한 정수 |
| F6 | 종합 점수로 판정을 붙인다: 80 이상 강력 추천, 60–79 추천, 40–59 보통, 40 미만 비추천 |
| F7 | 부족한 점은 공부할 대상이 드러나게 짧은 기술 이름으로 받는다 (예: `Docker`, `AWS`, `Spring Boot`) |
| F8 | LLM 응답이 형식에 맞지 않으면(항목 누락, 0–100 밖 점수, 요약 없음) 그 공고는 실패(단계: 채점)로 처리하고 시트에 넣지 않는다 |
| F9 | 시트 뒤쪽에 종합점수, 판정, 기술, 경력, 방향, 강점, 부족한 점 열을 추가한다. 강점과 부족한 점은 쉼표로 이어 한 칸에 넣는다 |
| F10 | v0.2의 집계 출력(가져옴/새로 저장/건너뜀/실패)을 그대로 쓰고, 실패 단계 이름을 `요약` 대신 `채점`으로 출력한다 |

### 스킬 갭 분석

| ID | 내용 |
| --- | --- |
| F11 | 실행 옵션 `--gaps`를 주면 공고 수집을 하지 않고, 시트에 저장된 공고의 부족한 점과 종합 점수만 읽어 분석한다 |
| F12 | 부족한 점마다 (100 − 종합 점수) / 100을 가중치로 더한다. 점수가 낮은 공고일수록 그 공고에서 나온 부족한 점이 더 크게 잡힌다 |
| F13 | 대소문자와 앞뒤 공백만 다른 이름은 같은 기술로 센다 |
| F14 | 가중 합 순으로 상위 10개를 터미널에 출력한다. 각 줄에 기술 이름, 가중 합, 나온 공고 수를 보인다 |
| F15 | 점수가 없는 줄(v0.3 이전에 저장한 공고)은 분석에서 빼고, 뺀 줄 수를 함께 출력한다. 분석할 줄이 없으면 그렇게 출력하고 끝낸다 |

### 점수 기준 (F4)

| 점수 | 기술 | 경력 | 커리어 방향 |
| --- | --- | --- | --- |
| 80–100 | 필수 요건이 내 주력 기술 | 같은 분야·같은 종류의 일을 해 봄 | 희망 방향과 거의 같음 |
| 60–79 | 대부분 맞고 배울 수 있는 빈칸 1–2개 | 관련 경험이 있고 옮겨 쓸 수 있음 | 대체로 맞지만 일부만 겹침 |
| 40–59 | 일부만 맞고 공부가 꽤 필요 | 인접 경험, 설득이 필요함 | 할 수는 있지만 방향과 거리가 있음 |
| 0–39 | 거의 맞지 않음 | 관련 없음 | 방향과 반대 |

| ID | 내용 |

| N5 | LLM 응답 검증 실패, 프로필 없음, 시트에 점수 없는 줄을 가짜 데이터로 테스트한다 |

## 하지 않는 것

- 탈락 조건(지역, 언어 등) 검사. 지역·경력은 v0.2 필터가 이미 거른다
- 문화 적합도. 사람인 API 정보로는 근거가 없다
- 이미 저장된 공고 다시 채점. v0.3 이전에 저장한 줄은 점수 없이 남는다
- 학습 계획 생성(학습 자료 추천 등). v0.3은 부족한 기술 순위까지만
- 비슷한 기술 이름 합치기(예: `도커`와 `Docker`)
- 상세 본문 크롤링, 공고 본문 검사, 마감 임박 표시

## 알려진 한계

- 채점 근거는 사람인 API가 주는 직무명, 경력, 학력, 키워드뿐이다. 상세 본문이 없어 점수가 거칠 수 있다. 상세 본문 크롤링 버전에서 나아진다
- LLM 점수는 실행마다 조금씩 다를 수 있다. 기준표로 흔들림을 줄이지만 없애지는 못한다

## 결정할 것

1. 프로필 파일이 없을 때: 멈춤(F2, 추천) 또는 v0.2처럼 요약만 저장
2. 스킬 갭 결과 위치: 터미널(F14, 추천) 또는 시트 새 탭
3. 가중치: 기술 40 / 경력 30 / 방향 30 (F5, 원본 30/25/30에서 문화 15를 빼고 다시 나눔)
