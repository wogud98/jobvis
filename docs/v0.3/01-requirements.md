# v0.3 요구사항

2026-10-20 확정.

## 목표

공고 처리를 두 단계로 나눈다.

1. 수집: 사람인 API로 공고를 모아 시트에 저장한다. LLM을 부르지 않는다.
2. 평가: 내 프로필과 공고를 비교해 적합도 점수, 별점, 강점, 부족한 점을 시트에 채운다. 사용자가 고른 공고만, 또는 점수 없는 공고 전부를 평가한다.

저장된 공고들의 부족한 점을 모아 내가 무엇을 공부해야 하는지도 보여준다.

참고: [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)(MIT)의 적합도 기준(`04-job-evaluation.md`)과 스킬 갭 분석(`/upskill`). [로드맵 후보](../roadmap.md#다음-버전-후보) 1, 2.

## 실행 방법

| 명령 | 하는 일 |
| --- | --- |
| `python main.py --keyword 백엔드 ...` | 수집만 |
| `python main.py --score` | "평가" 열을 체크한 공고만 평가 |
| `python main.py --score all` | 점수 없는 공고 전부 평가 |
| `python main.py --keyword 백엔드 ... --score all` | 수집이 끝나면 이어서 점수 없는 공고 전부 평가 |
| `python main.py --gaps` | 스킬 갭 분석 |

## 기능 요구사항

### 수집

| ID | 내용 |
| --- | --- |
| F1 | v0.2의 수집 기능(F1–F6, F8, F11: 조건 입력, 코드 변환, 경력 거르기, 개수, 중복 방지, 모르는 이름 처리)을 그대로 쓴다 |
| F2 | 수집 단계에서는 LLM을 부르지 않는다. 자격요건 요약 대신 공고 제목(사람인 `position.title`, 시트 "직무" 열)만 저장하고 "자격요건" 칸은 비워 둔다 |
| F3 | 평가에 쓸 공고 정보(경력, 학력, 키워드)를 시트 열에 함께 저장한다. 평가 단계는 사람인 API를 다시 부르지 않고 시트에서 읽는다 |
| F4 | 수집 결과로 가져옴, 새로 저장, 건너뜀, 실패 수를 출력한다. 실패 단계는 `저장` 하나다 |

### 평가

| ID | 내용 |
| --- | --- |
| F5 | 내 프로필을 마크다운 파일로 받는다. 실행 옵션 `--profile`로 경로를 지정하고, 생략하면 `profile.md`를 쓴다. 형식 예시는 `profile.example.md`로 저장소에 둔다 |
| F6 | 평가를 하는데 프로필 파일이 없거나 비어 있으면 사람인 API와 LLM을 부르기 전에 멈추고, 파일 경로와 예시 파일 이름을 출력한다 |
| F7 | `--score`는 "평가" 열이 체크(TRUE)된 줄을 평가한다. 이미 점수가 있어도 다시 평가하고, 끝나면 체크를 해제한다 |
| F8 | `--score all`은 종합점수가 비어 있는 줄을 모두 평가한다 |
| F9 | 공고 한 건마다 LLM을 한 번 불러 아래를 함께 받는다: 자격요건 한 줄 요약(60자 이내, "자격요건" 칸에 저장), 항목별 점수, 강점(최대 3개), 부족한 점(최대 3개) |
| F10 | 채점 항목은 기술, 경력, 문화, 커리어 방향 네 가지이고 각각 0–100 정수다. 문화는 공고에 근거가 없으면 점수 대신 "근거 없음"으로 받는다. 항목별 기준표는 프롬프트에 넣는다 (아래 "점수 기준") |
| F11 | 종합 점수는 프로그램이 계산한다. 가중치는 원본을 따라 기술 30, 경력 25, 문화 15, 커리어 방향 30이다. 근거 없음인 항목은 빼고 남은 항목의 가중치 비율로 평균을 낸 뒤 반올림한 정수로 한다 |
| F12 | 종합 점수로 판정을 붙인다: 80 이상 강력 추천, 60–79 추천, 40–59 보통, 40 미만 비추천 |
| F13 | 별점은 종합 점수 ÷ 20을 반올림한 0–5개 별로 `★★★★☆`처럼 표시하고, 종합 점수 숫자 열 옆에 둔다 |
| F14 | 부족한 점은 공부할 대상이 드러나게 짧은 기술 이름으로 받는다 (예: `Docker`, `AWS`, `Spring Boot`) |
| F15 | LLM 응답이 형식에 맞지 않으면(항목 누락, 0–100 밖 점수, 요약 없음) 그 줄은 실패(단계: 채점)로 처리하고 시트를 바꾸지 않는다 |
| F16 | 평가 결과로 대상, 완료, 건너뜀, 실패 수를 출력한다. 경력·학력·키워드 열이 모두 빈 줄(v0.3 이전에 저장한 줄)은 건너뜀으로 센다 |

### 스킬 갭 분석

| ID | 내용 |
| --- | --- |
| F17 | `--gaps`는 공고 수집과 평가를 하지 않고, 시트에 저장된 부족한 점과 종합 점수만 읽어 분석한다 |
| F18 | 부족한 점마다 (100 − 종합 점수) / 100을 가중치로 더한다. 점수가 낮은 공고일수록 그 공고에서 나온 부족한 점이 더 크게 잡힌다 |
| F19 | 대소문자와 앞뒤 공백만 다른 이름은 같은 기술로 센다 |
| F20 | 가중 합 순으로 상위 10개를 터미널에 출력한다. 각 줄에 기술 이름, 가중 합, 나온 공고 수를 보인다 |
| F21 | 점수가 없는 줄은 분석에서 빼고, 뺀 줄 수를 함께 출력한다. 분석할 줄이 없으면 그렇게 출력하고 끝낸다 |

### 점수 기준 (F10)

| 점수 | 기술 | 경력 | 문화 | 커리어 방향 |
| --- | --- | --- | --- | --- |
| 80–100 | 필수 요건이 내 주력 기술 | 같은 분야·같은 종류의 일을 해 봄 | 일하는 방식이 내 선호와 잘 맞음 | 희망 방향과 거의 같음 |
| 60–79 | 대부분 맞고 배울 수 있는 빈칸 1–2개 | 관련 경험이 있고 옮겨 쓸 수 있음 | 대체로 맞음 | 대체로 맞지만 일부만 겹침 |
| 40–59 | 일부만 맞고 공부가 꽤 필요 | 인접 경험, 설득이 필요함 | 맞지 않는 부분이 있음 | 할 수는 있지만 방향과 거리가 있음 |
| 0–39 | 거의 맞지 않음 | 관련 없음 | 크게 맞지 않음 | 방향과 반대 |

## 하지 않는 것

- 상세 본문 크롤링 (v0.4). v0.3 평가는 API 정보(직무명, 경력, 학력, 키워드)만 쓴다
- 레이더 차트. 여유가 되면 웹 화면(v1.0)에서 한다
- 탈락 조건(지역, 언어 등) 검사. 지역·경력은 수집 필터가 이미 거른다
- 학습 계획 생성(학습 자료 추천 등). v0.3은 부족한 기술 순위까지만
- 비슷한 기술 이름 합치기(예: `도커`와 `Docker`)
- 공고 본문 검사, 마감 임박 표시

## 알려진 한계

- API 정보만으로는 채점 근거가 얇다. 문화는 대부분 근거 없음이 되고, 다른 항목도 점수가 거칠 수 있다. v0.4에서 상세 본문이 들어오면 나아진다
- LLM 점수는 실행마다 조금씩 다를 수 있다. 기준표로 흔들림을 줄이지만 없애지는 못한다
- 평가하지 않은 줄은 "자격요건" 칸이 비어 있다. API 정보만으로는 요약이 제목과 크게 다르지 않고, v0.4에서 본문이 들어오면 쓸모가 커진다

## 확정한 것

2026-10-20 사용자와 대화에서 정함.

- 수집과 평가를 두 단계로 나눈다. 평가는 고른 공고 또는 점수 없는 공고 전부
- 상세 본문 크롤링은 v0.4
- 시각화는 별점과 숫자. 레이더 차트는 웹 화면에서 여유가 되면
- 가중치는 ai-job-search 원본(30/25/15/30). 근거 없는 항목은 빼고 다시 나눈다
- 수집 단계는 요약 없이 공고 제목만 저장하고, 요약은 평가 호출에서 함께 받아 "자격요건" 칸을 채운다
- 프로필 파일이 없으면 멈춤(F6), 스킬 갭 결과는 터미널(F20)
