# v0.7.4 요구사항

2026-10-23 확정(재리 "오키!" 06:35, F6–F8은 "진행" 06:46). 기술 모아보기와 메일 창을 다듬고, 공고 이미지 넣기를 버튼 하나로 줄인다. 수집·점수 계산·저장 칸·메일 내용은 바꾸지 않는다.

## 사용자 의견과 결정

- "1건들이 너무너무 많다. 세로로 나열된 1건들은 순위를 확인하는 용도가 아닌, 무엇이 있는지 체킹하는 정도이니 따로 묶어서 보여주도록"(06:32) → 막대는 2건 이상, 1건은 아래 칩 묶음(제안 → "오키!")
- "메일 보내기에서 보이는 공고 모두 보내기 버튼의 text가 버튼 크기랑 너무 같으니 늘리자"(06:35)
- "메일 보내기에서 공고 리스트가 길 때 2줄 차지하는 경우가 없도록 가로 크기 조금 더 늘리자"(06:35)
- "기술 모아보기 excel로 저장하는 기능, text로 전체 복사하는 기능 추가"(06:35) → 엑셀은 새 의존성 없이 엑셀에서 바로 열리는 CSV(UTF-8 BOM)
- "이미지 필요의 받은함이라는 단어가 매우 어색하다"(06:43) → 단어보다 세 단계 흐름(저장 → 위 받은함 카드에서 읽기 → 다시 평가)이 문제. 카드 버튼 하나로(제안)
- "이미지 등록해서 저장한 공고는 읽으면 바로 평가가 되도록"(06:44) → 저장 → 글자 읽기 → 그 공고만 다시 평가("진행" 06:46)

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 기술 모아보기 두 탭에서 막대 순위는 2건 이상인 것만. 1건짜리는 아래 "1건씩 나온 것 N개" 칩 묶음(가로로 이어지고 줄바꿈, 이름순, 내 기술은 초록). 위 요약 "많이 찾는 기술 N개 중"은 전체 기준 그대로 |
| F2 | 메일 창 "보이는 공고 모두 고르기" 버튼 글자 둘레에 여유를 둔다 |
| F3 | 메일 창을 넓혀(중간 폭) 공고 줄이 한 줄로 보인다. 그래도 길면 줄을 바꾸지 않고 끝을 "…"로 줄인다 |
| F4 | 기술 모아보기 "📥 엑셀로 저장": 두 탭 내용을 CSV 한 파일(구분·순위·이름·공고 수·내 기술·가중치)로 내려받는다. 엑셀에서 한글이 깨지지 않는다. 내려받아도 창은 닫히지 않는다 |
| F5 | 기술 모아보기 "📋 전체 복사": 두 탭 내용을 글로 클립보드에 복사한다. 1건짜리는 "1건씩: …" 한 줄. 누른 뒤 버튼 글자가 "✓ 복사했습니다"로 바뀐다 |
| F6 | 화면에서 "받은함" 단어와 위쪽 받은함 카드를 없앤다. 자세히의 공고 이미지 칸에는 이미지 넣기와 버튼 **🖼 이미지로 다시 평가** 하나만. 이미지를 넣기 전에는 누를 수 없다. OCR이 없으면 넣는 칸 대신 설치 안내만 |
| F7 | 버튼을 누르면 이미지를 저장하고, 글자를 읽어 본문을 채우고, **그 공고만** 다시 평가한다. 진행·결과는 수집·평가처럼 위 실행 칸에 |
| F8 | 그 공고 본문을 채우지 못하면(글자 없음·OCR 실패) 평가하지 않고 이유를 알린다. 프로필·키가 없으면 이미지를 저장하지 않고 할 일을 알린다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 새 의존성 없음. CSV는 파이썬 기본 `csv`, 복사는 v0.6.1 화면 스크립트(`SCHEME_SYNC`) 한 곳 |
| N2 | 기술 모아보기는 LLM을 부르지 않는다. 엑셀·글은 화면에 보이는 목록(필터 적용)과 같은 내용. 이미지로 다시 평가는 그 공고 1건만 LLM을 부른다 |
| N3 | 밝은·어두운 테마 모두 새 버튼이 다른 보통 버튼과 같은 모양 |
| N4 | 명령줄 `--inbox`·`--score`는 그대로 |

- 수집 후 자동 평가(재리 결정)
