# v0.7.8 요구사항

2026-11-06 확정(재리 "진행" 01:18). 글자가 그림으로 된 PDF 이력서도 "이력서로 채우기"로 읽게 한다. 글자가 있는 PDF·Word·txt·md는 지금 그대로.

## 사용자 의견과 결정

- "프로필 입력하면 읽을 수 없는게 포함되어 있다고 오류뜸 (PDF)"(01:14) → 확인: 이유는 "글자를 뽑지 못함 (스캔 이미지 PDF이거나 빈 파일)". pypdf는 글자로 저장된 것만 뽑아 그림 글자는 0자 → LLM에 보내기 전에 멈춤
- "LLM을 쓰는 거 아니야? 왜 못 읽어"(01:16) → 내 안: 글자가 안 나오는 PDF는 파일째 LLM에 보냄(Gemini·Claude 모두 PDF 직접 읽음). OCR·쪽 그림 변환(pypdfium2)보다 단순하고 의존성 없음 → "진행"

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | PDF에서 뽑은 글자가 없으면(공백만 포함) 건너뛰지 않고 PDF 파일 자체를 LLM에 보낸다 |
| F2 | 글자가 있는 파일과 파일째 보내는 PDF가 섞이면 한 번의 LLM 호출로 함께 보낸다. 글자 쪽 규칙(앞 20,000자, 파일 이름 제목)은 그대로 |
| F3 | 파일째 보내는 PDF는 10쪽까지만 받는다. 넘으면 그 파일만 건너뛰고 "10쪽 초과 (그림 PDF)"를 보인다. 파일당 10MB 제한은 그대로 |
| F4 | 깨진 PDF·빈 파일(쪽 0개)은 지금처럼 그 파일만 건너뛰고 이유를 보인다 |
| F5 | 쓰는 모델이 PDF를 받지 못해 오류가 나면 아무 칸도 바꾸지 않고 "이 모델은 그림 PDF를 읽지 못함"을 보인다. 키·파일 내용은 보이지 않는다 |
| F6 | 업로드 칸 안내를 "PDF(글자 있는 것)"에서 "PDF(그림 PDF는 파일 전체가 전송됨)"으로 바꾼다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | 새 의존성 없음. OCR 없는 기본 Docker 이미지에서도 된다 |
| N2 | 파일은 지금처럼 디스크에 저장하지 않고, 파일 내용·LLM 응답은 로그·오류 메시지에 쓰지 않는다 (v0.5.2 N2) |
| N3 | 모델은 `init_chat_model(LLM_MODEL)` 그대로. 제공자 클래스를 직접 쓰지 않는다 |
| N4 | 테스트는 실제 LLM을 부르지 않는다. 그림 PDF, 섞인 파일, 10쪽 초과, 모델 오류를 가짜 LLM으로 검증한다 |

## 하지 않는 것

- 글자가 있는 PDF도 파일째 보내기(글자로 충분하고 무료 한도를 아낌)
- PaddleOCR로 PDF 읽기, 쪽 그림 변환 의존성 추가
- 쪽 수 제한을 사용자가 고르는 옵션
