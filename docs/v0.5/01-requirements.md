# v0.5 요구사항

2026-10-21 확정. 같은 날 범위를 넓힘: Streamlit 보기 화면을 넣고 프로필 입력을 화면으로 옮김.

## 목표

시트 칸에 흩어져 읽기 어려운 평가 결과를 PC 브라우저 화면으로 본다. 직접 써 보면서 불편한 점을 다음 버전에서 고친다. 적합도의 근거가 되는 내 프로필도 같은 화면에서 정해진 형식으로 입력한다.

1. 보기 화면: Streamlit으로 시트를 읽어 공고를 점수순 카드로 보여준다. 화면은 읽기만 하고, 수집과 평가는 지금처럼 터미널에서 한다.
2. 프로필: `profile.yaml` 한 파일. 점수 항목 4개(기술, 경력, 문화, 방향)와 칸을 맞춘다. 화면의 프로필 탭에서 입력하고, 파일을 직접 고쳐도 된다. 평가(`--score`)할 때 읽는다.

## 실행 방법

| 명령 | 하는 일 |
| --- | --- |
| `streamlit run app.py` | 보기 화면과 프로필 탭을 PC 브라우저(localhost)로 연다 |
| `python main.py --keyword ...`, `--score`, `--gaps` | v0.4와 같음. `--score`는 `profile.yaml`을 읽음 |

## 현재 상태 (v0.3–v0.4)

- 결과는 구글 시트에만 있음. 요약·강점·부족한 점이 셀에 길게 들어가 읽기 어려움 (2026-10-21 FDE 평가 탭을 보고 사용자가 지적)
- 프로필은 `profile.md` 자유 마크다운, `--profile`로 경로 지정 (v0.3 F5). 없거나 비면 멈추고 `profile.example.md` 안내 (v0.3 F6)
- 프로필 전체를 프롬프트에 그대로 넣음. 칸 구분이 없어 경력 연수 등이 빠져도 알 수 없음

## 기능 요구사항

### 보기 화면

| ID | 내용 |
| --- | --- |
| F1 | `streamlit run app.py`로 연다. 화면은 탭 두 개: 공고, 프로필 |
| F2 | 공고 탭은 시트의 모든 줄을 읽어 점수 높은 순 카드로 보여준다. 카드에는 회사, 직무, 종합점수, 별점, 판정, 마감일, 출처를 보인다. 점수 없는 공고는 "평가 전"으로 맨 아래에 둔다 |
| F3 | 카드를 누르면 펼쳐서 요약(자격요건, v0.4 F18 요약 칸), 항목별 점수(기술, 경력, 문화, 방향), 강점, 부족한 점을 보여준다. 빈 칸은 "없음"으로 보인다 |
| F4 | 카드마다 원문 링크를 둔다. 새 탭에서 열린다 |
| F5 | 위쪽에 공고별 종합점수 막대 차트를 둔다. 필터를 바꾸면 차트도 같은 공고만 보인다 |
| F6 | 필터: 출처(사람인, 잡코리아), 경력(시트 경력 칸에 있는 값 목록), 평가 전 공고 보기 켜기/끄기. 출처 칸이 없는 예전 줄은 출처 "미상"으로 묶는다 |
| F7 | 시트는 열 때 한 번 읽고, "새로고침" 버튼을 누르면 다시 읽는다 |
| F8 | 화면은 시트에 쓰지 않고, LLM과 공고 사이트를 부르지 않는다 |
| F9 | 시트 읽기에 실패하면(인증 파일 없음, 시트 없음, 네트워크 오류) 화면에 이유와 확인할 것을 보인다. 인증 정보는 보이지 않는다 |
| F10 | 시트에 공고가 하나도 없으면 "공고 없음, 터미널에서 수집하세요"와 명령 예시를 보인다 |

### 프로필 파일

#### 형식

```yaml
# 기술 점수에 씀
skills:
  main: [Python, SQL]          # 주력 (1개 이상 필수)
  can_use: [Java, Git, Linux]  # 다룰 수 있음
  tried: [Docker, FastAPI]     # 써 본 적 있음
  certificates: [정보처리기사]  # 자격증

# 경력 점수에 씀
experience:
  years: 0                     # 경력 연수, 신입은 0 (필수)
  projects:
    - LangGraph로 채용공고 수집·평가 에이전트 개발 (JOBVIS)
  degree: 대학교 졸업(4년), 컴퓨터공학   # 최종 학력과 전공
  training:
    - ○○ 부트캠프 백엔드 과정 수료

# 방향 점수에 씀
direction:
  jobs: [백엔드 개발, AI 서비스 개발]   # 희망 직무 (1개 이상 필수)
  goals: LLM을 활용한 서비스 개발, API 서버 설계
  locations: [서울, 경기]       # 희망 근무 지역

# 문화 점수에 씀 (비워도 됨)
culture:
  - 코드 리뷰와 문서화를 하는 팀
  - 신입 교육이나 멘토링이 있는 곳
```

| ID | 내용 |
| --- | --- |
| F11 | 프로필을 위 형식의 `profile.yaml`로 받는다. `--profile` 기본값을 `profile.md`에서 `profile.yaml`로 바꾼다 |
| F12 | 필수 칸: `skills.main`(1개 이상), `experience.years`(0–50 정수), `direction.jobs`(1개 이상). 나머지는 비워도 된다 |
| F13 | `--score`에서 필수 칸이 비었거나 형식이 틀리면 LLM과 시트를 부르기 전에 멈추고, 어느 칸이 왜 틀렸는지 출력한다 |
| F14 | 모르는 칸이 있으면 경고만 출력하고 계속한다 (오타 알림용) |
| F15 | `profile.example.yaml`을 저장소에 두고 `profile.example.md`는 지운다 |
| F16 | `--score`를 실행했는데 `profile.yaml`이 없으면 멈추고, 화면 프로필 탭(`streamlit run app.py`)이나 `profile.example.yaml` 복사로 만들라고 안내한다. 예전 `profile.md`가 있으면 그 사실도 알린다. 자동 변환은 하지 않는다 |

### 프로필 탭

| ID | 내용 |
| --- | --- |
| F17 | 프로필 탭은 `profile.yaml`의 모든 칸을 입력란으로 보여준다. 파일이 있으면 그 내용으로 채워 연다 |
| F18 | 경력 연수는 가로 슬라이더(0–30년, 1년 단위)로 고른다 |
| F19 | 목록 칸(기술, 자격증, 프로젝트, 교육 이수, 희망 직무, 희망 지역, 선호 문화)은 한 줄에 하나씩 적는다 |
| F20 | "저장"을 누르면 F12 필수 칸을 검사한다. 틀리면 어느 칸인지 보이고 저장하지 않는다. 맞으면 `profile.yaml`에 쓰고 저장 시각을 보인다 |
| F21 | 파일을 직접 고친 내용과 화면이 어긋나지 않게, 탭을 열 때마다 파일을 다시 읽는다. 파일이 깨져 있으면(잘못된 YAML) 덮어쓰지 않고 이유를 보인다 |

### 평가

| ID | 내용 |
| --- | --- |
| F22 | LLM에 넘기는 프로필을 점수 항목별 제목(기술, 경력, 문화, 방향)으로 나눈 글로 바꿔 넣는다. 점수 기준표·가중치·계산은 v0.3 그대로 |

| F24 | `culture`가 비어 있으면 프롬프트에 "선호 문화 정보 없음"을 넣는다. 문화 점수가 null이면 v0.3처럼 가중치를 다시 나눈다 |

### 점수 보정

2026-10-21 FDE 공고 시험 평가(`gemini-flash-lite-latest`, v0.3 프롬프트, 17건)에서 점수가 후하게 나왔다. 3년 이상 요구 공고에 경력 2년 8개월인데 경력 75점, 방향 점수 80–95로 거의 고정, 본문 없는 공고 3건도 54–74점. LLM이 매긴 점수는 그대로 두고, 코드가 정한 규칙으로 깎는다. 원래 점수와 깎은 이유는 시트에 남긴다.

| ID | 내용 |
| --- | --- |
| F25 | LLM 응답에 `required_years`를 더한다. 공고가 요구하는 최소 경력 연수(정수). 신입·경력무관은 0, 공고에 없으면 null. "3~5년"이면 3 |
| F26 | 경력 상한: 부족 연수 = `required_years` − 프로필 `experience.years`. 1년 부족이면 경력점수 최대 60, 2년이면 45, 3년 이상이면 30. LLM 점수가 상한보다 높을 때만 낮춘다. `required_years`가 null이면 적용하지 않는다 |
| F27 | 경력이 부족한 공고(F26 적용)는 종합점수를 79점 위로 주지 않는다. 판정은 "추천"까지 |
| F28 | 신뢰도: 본문 상태(v0.4 F15)로 정한다. 글자·글자+이미지 → 높음, 이미지 일부 못 읽음 → 보통, 본문 미확보·원문 파일 없음 → 낮음 |
| F29 | 신뢰 낮음이면 종합점수를 69점 위로 주지 않는다. 시트 정보(제목·경력)만 보고 매긴 점수라서 |
| F30 | 방향 점수 기준표를 바꾼다. 80–100 공고 주요업무가 희망 직무와 같고 하고 싶은 일(`direction.goals`)과도 겹침 / 60–79 희망 직무와 같지만 하고 싶은 일과는 일부만 겹침 / 40–59 직무 이름만 비슷하고 실제 업무는 다름(예: 제목은 FDE, 본문은 기술영업) / 0–39 다른 직무 |
| F31 | 방향 규칙을 프롬프트에 넣는다: 제목만 보고 80점 이상 주지 않는다. 본문 주요업무에서 근거를 찾지 못하면 70점 이하로 준다 |
| F32 | 시트에 "신뢰"(AB), "보정"(AC) 열을 붙인다. "보정"에는 적용한 규칙과 원래 점수를 적는다. 예: "경력 75→60 (3년 요구, 2년)", "종합 82→79 (경력 부족)", "종합 74→69 (신뢰 낮음)". 적용한 것이 없으면 빈칸 |
| F33 | v0.4 F17의 판정 옆 "(본문 미확보)" 표시는 "신뢰" 열로 옮기고 판정에는 붙이지 않는다. 판정 칸은 강력 추천·추천·보통·비추천과 F36의 "제외 (경력 요구)"만 쓴다 |
| F34 | 화면 공고 카드(F2, F3)에 신뢰와 보정 내용을 보인다. 신뢰 낮음 카드는 흐리게 보인다 |
| F35 | 보정 규칙(F26, F27, F29)과 순서는 코드에서 계산한다. 순서: 신입 제외(F36) → 경력 상한 → 종합점수 계산 → 종합 상한(F27, F29 중 낮은 값) → 별점·판정 |
| F36 | 신입 제외: 프로필 `experience.years`가 0이고 시트 경력 칸에 "신입"·"무관"이 없으면(예: "경력 3년↑") LLM을 부르지 않는다. 판정 칸에 "제외 (경력 요구)"만 쓰고 점수 칸은 비운다. 평가 결과 출력에서 "제외" 수를 따로 센다. 경력 칸이 빈 줄은 제외하지 않고 평가한다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | `profile.yaml`을 `.gitignore`에 넣고 커밋하지 않는다 |
| N2 | 프로필 내용을 로그·오류 메시지에 그대로 찍지 않는다. 오류에는 칸 이름만 쓴다 |
| N3 | 의존성: `streamlit`을 `requirements.txt`에 넣는다. `PyYAML`도 적는다(이미 `langchain`과 함께 설치돼 있음, 6.0.3 확인). 차트는 Streamlit 기본 차트로 그려 다른 차트 라이브러리를 넣지 않는다 |
| N4 | 화면은 PC 전용, 내 PC에서만 연다(localhost). 배포하거나 외부에 공개하지 않는다. 수집한 공고를 공유하지 않는 v0.4 N6과 같은 이유 |
| N5 | 정렬·필터·카드 내용 만들기·프로필 검사·YAML 읽고 쓰기는 Streamlit 밖 함수로 두고 가짜 데이터로 테스트한다. 시트 읽기 실패, 빈 시트, 점수 없는 줄, 출처 없는 예전 줄, 필수 칸 누락, 잘못된 연수, 깨진 YAML, 모르는 칸 경고, 프로필 없음, 예전 `profile.md`만 있음, 문화 비었을 때 프롬프트를 포함한다. 실제 API 호출 없음 |
| N6 | 보정은 가짜 LLM 응답으로 테스트한다: 경력 부족 0·1·2·3년 이상, `required_years` null, 상한보다 낮은 점수는 그대로, 경력 부족 + 신뢰 낮음 동시(낮은 상한), 신입 제외(경력 글자별, 빈 경력 칸, LLM 안 부름), 신뢰 세 단계, "보정" 열 문구, 판정에 "(본문 미확보)"가 붙지 않음, 방향 규칙이 프롬프트에 들어감 |

## 하지 않는 것

- 기술 점수 몰림(17건 중 9건 65점)과 문화 점수 null(17건 중 15건) 보정. 이번 시험에서 보였지만 요청 범위 밖이라 다음 버전 후보로 둔다
- 보정 규칙 숫자(상한 60/45/30, 79, 69)를 설정 파일로 빼기. 써 보고 바꿀 일이 잦으면 그때

- 화면에서 수집·평가 실행. 터미널로 한다. 써 보면서 필요하면 다음 버전 후보로 둔다
- 추천 검색어 자동완성. 검색어 입력이 화면에 없어서 화면에서 수집할 때 함께 본다
- 레이더 차트(항목별 다각형). 막대 차트를 써 보고 정한다
- FastAPI. 보류(2026-10-21 사용자 결정)
- 모바일 화면, 배포, 로그인
- 터미널 질문으로 프로필 만들기와 `--init-profile`. 화면 프로필 탭으로 대신함
- 이력서·자소서 글에서 LLM으로 프로필 자동 채우기. 화면 입력이 있어 필요 없음(2026-10-21 사용자 결정)
- 예전 `profile.md` 자동 변환, 프로필 여러 개 관리

## 확정한 것

2026-10-21 사용자와 대화에서 정함.

- 프로필 입력을 v0.5로 넣고 이후 로드맵 버전을 한 칸씩 미룬다. v0.4 구현을 먼저 한다
- 형식은 `profile.yaml`. 점수 항목(기술, 경력, 문화, 방향)과 칸을 맞춘다. 학력, 자격증, 희망 지역 칸을 넣는다
- FastAPI는 보류하고 Streamlit 화면을 먼저 한다. 먼저 시트를 읽기만 하는 보기 화면을 만들고, 써 보면서 기능을 붙인다
- 프로필 입력은 그 화면 위에서 한다
- 점수 보정도 v0.5에 넣는다. 경력 부족 상한 60/45/30·종합 79, 신뢰 낮음 종합 69, 경력 연수는 1년 단위 유지, 신입은 경력 요구 공고를 평가에서 제외, 본문 미확보 표시는 판정 대신 신뢰 열에
