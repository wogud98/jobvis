# v0.5 요구사항

2026-10-21 확정.

## 목표

적합도 점수의 근거가 되는 내 프로필을 정해진 형식으로 받는다. 점수 항목 4개(기술, 경력, 문화, 방향)와 프로필 칸을 1:1로 맞춰 점수 근거를 분명하게 한다.

1. 형식: `profile.yaml` 한 파일. 저장소에는 `profile.example.yaml`만 둔다.
2. 시점: 평가(`--score`)할 때 읽는다. 파일이 없으면 터미널 질문으로 만들어 준다. 수집과 `--gaps`는 프로필을 읽지 않는다(v0.3 그대로).
3. 장소: 지금은 터미널과 파일. 화면 입력(경력 슬라이더 등)은 Streamlit 버전에서 같은 파일을 읽고 쓴다.

## 현재 상태 (v0.3)

- `profile.md` 자유 마크다운, `--profile`로 경로 지정 (v0.3 F5)
- 없거나 비면 수집·LLM 호출 전에 멈추고 `profile.example.md` 안내 (v0.3 F6)
- 내용 전체를 프롬프트에 그대로 넣음. 칸 구분이 없어 경력 연수 등이 빠져도 알 수 없음

## 형식

```yaml
# 기술 점수에 씀
skills:
  main: [Python, SQL]          # 주력 (1개 이상 필수)
  can_use: [Java, Git, Linux]  # 다룰 수 있음
  tried: [Docker, FastAPI]     # 써 본 적 있음
  certificates: [정보처리기사]  # 자격증

# 경력 점수에 씀
experience:
  years: 0                     # 경력 연수, 신입은 0 (필수)
  projects:
    - LangGraph로 채용공고 수집·평가 에이전트 개발 (JOBVIS)
  degree: 대학교 졸업(4년), 컴퓨터공학   # 최종 학력과 전공
  training:
    - ○○ 부트캠프 백엔드 과정 수료

# 방향 점수에 씀
direction:
  jobs: [백엔드 개발, AI 서비스 개발]   # 희망 직무 (1개 이상 필수)
  goals: LLM을 활용한 서비스 개발, API 서버 설계
  locations: [서울, 경기]       # 희망 근무 지역

# 문화 점수에 씀 (비워도 됨)
culture:
  - 코드 리뷰와 문서화를 하는 팀
  - 신입 교육이나 멘토링이 있는 곳
```

## 기능 요구사항

### 파일

| ID | 내용 |
| --- | --- |
| F1 | 프로필을 위 형식의 `profile.yaml`로 받는다. `--profile` 기본값을 `profile.md`에서 `profile.yaml`로 바꾼다 |
| F2 | 필수 칸: `skills.main`(1개 이상), `experience.years`(0–50 정수), `direction.jobs`(1개 이상). 나머지는 비워도 된다 |
| F3 | 필수 칸이 비었거나 형식이 틀리면 LLM과 시트를 부르기 전에 멈추고, 어느 칸이 왜 틀렸는지 출력한다 |
| F4 | 모르는 칸이 있으면 경고만 출력하고 계속한다 (오타 알림용) |
| F5 | `profile.example.yaml`을 저장소에 두고 `profile.example.md`는 지운다 |

### 처음 만들기

| ID | 내용 |
| --- | --- |
| F6 | `--score`를 실행했는데 프로필 파일이 없으면 "지금 만들까요?"를 묻는다. 예를 고르면 필수 칸 3개만 터미널로 묻는다: 주력 기술, 경력 연수, 희망 직무 |
| F7 | 목록(주력 기술, 희망 직무)은 쉼표로 구분해 한 줄로 받는다 |
| F8 | 빈 답이나 잘못된 값(연수에 글자 등)을 넣으면 같은 질문을 다시 한다 |
| F9 | 답으로 `profile.yaml`을 만든다. 나머지 칸(자격증, 학력, 프로젝트, 교육 이수, 하고 싶은 일, 희망 지역, 선호 문화 등)은 빈 칸과 주석 예시로 넣어 편집기에서 채우게 한다. 만든 뒤 파일 경로와 "나머지 칸을 채우면 점수 근거가 늘어남"을 출력하고 평가를 이어 한다 |
| F10 | 실행 옵션 `--init-profile`로 필수 칸 3개를 다시 물어 파일을 새로 만든다. 파일이 있으면 덮어쓸지 먼저 묻는다 |
| F11 | 입력을 받을 수 없는 환경(CI, 파이프 입력)에서는 묻지 않고 v0.3 F6처럼 경로와 예시 파일 이름을 출력하고 멈춘다 |
| F12 | `profile.yaml`이 없고 예전 `profile.md`가 있으면 그 사실을 알려 주고 F6 질문으로 넘어간다. 자동 변환은 하지 않는다 |

### 평가

| ID | 내용 |
| --- | --- |
| F13 | LLM에 넘기는 프로필을 점수 항목별 제목(기술, 경력, 문화, 방향)으로 나눈 글로 바꿔 넣는다. 점수 기준표·가중치·계산은 v0.3 그대로 |
| F14a | 자격증은 기술, 학력은 경력, 희망 지역은 방향 제목 아래에 넣는다. 공고의 학력·지역 조건과 비교하는 근거로 쓴다 |
| F14 | `culture`가 비어 있으면 프롬프트에 "선호 문화 정보 없음"을 넣는다. 문화 점수가 null이면 v0.3처럼 가중치를 다시 나눈다 |

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | `profile.yaml`을 `.gitignore`에 넣고 커밋하지 않는다 |
| N2 | 프로필 내용을 로그·오류 메시지에 그대로 찍지 않는다. 오류에는 칸 이름만 쓴다 |
| N3 | 의존성: `PyYAML`을 `requirements.txt`에 적는다. 이미 `langchain`과 함께 설치돼 있어 새로 받는 것은 없다 (6.0.3 확인) |
| N4 | 정상 읽기, 필수 칸 누락, 잘못된 연수, 깨진 YAML, 모르는 칸 경고, 필수 칸 질문으로 만들기(가짜 입력), 잘못된 답 다시 묻기, 덮어쓰기 거절, 입력 불가 환경, 예전 `profile.md`만 있음, 문화 비었을 때 프롬프트를 가짜 데이터로 테스트한다. 실제 API 호출 없음 |

## 하지 않는 것

- 화면 입력(Streamlit 프로필 화면, 경력 슬라이더). 화면 버전에서 같은 파일을 쓴다
- 이력서·자소서 글에서 LLM으로 프로필 자동 채우기. 화면 입력이 생기면 불필요해 빼기로 함(2026-10-21 사용자 결정)
- 터미널로 모든 칸 묻기. 필수 칸만 묻고 나머지는 파일에서 채움(2026-10-21 사용자 결정)
- 예전 `profile.md` 자동 변환
- 프로필 여러 개 관리

## 확정한 것

2026-10-21 사용자와 대화에서 정함.

- 프로필 입력을 v0.5로 넣고 이후 로드맵 버전을 한 칸씩 미룬다. v0.4 구현을 먼저 한다
- 형식은 `profile.yaml`. 점수 항목(기술, 경력, 문화, 방향)과 칸을 맞춘다
- 학력, 자격증, 희망 지역 칸을 넣는다
- 터미널에서는 필수 칸 3개만 묻고 나머지는 파일에서 채운다
- 이력서·자소서에서 자동 채우기는 하지 않는다. 화면 입력이 생기면 필요 없어짐
