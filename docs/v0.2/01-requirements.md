# v0.2 요구사항 (초안)

## 목표

조건(지역·직무·경력)에 맞는 사람인 공고를 여러 건 가져와 요약하고, 이미 저장한 공고는 건너뛰고 새 공고만 구글 시트에 저장한다.

## 기능 요구사항

| ID | 내용 |
| --- | --- |
| F1 | 실행 옵션으로 키워드, 지역, 직무, 경력, 가져올 개수를 받는다. 키워드 외에는 모두 선택 |
| F2 | 지역·직무는 사람이 읽는 이름(예: 서울, 백엔드)으로 입력하고, 프로그램이 사람인 코드로 바꿔 API 조건으로 보낸다 |
| F3 | 경력은 `신입` 또는 `경력` 중 하나로 받는다. 생략하면 경력으로 거르지 않는다 |
| F4 | 사람인 API에는 경력 조건이 없으므로, 받은 공고의 경력 정보(`experience-level`)로 프로그램이 거른다. `신입`은 신입·신입/경력·경력무관 공고를, `경력`은 경력·신입/경력·경력무관 공고를 남긴다 |
| F5 | 가져올 개수 기본값은 10건, 최대 110건. 사람인 API를 한 번만 호출한다 |
| F6 | 경력 조건이 있으면 API에 110건을 요청하고, 거른 결과에서 앞에서부터 요청한 개수만 쓴다 |
| F7 | 각 공고의 자격요건을 v0.1과 같은 방식으로 한 줄 요약한다 |
| F8 | 시트에 이미 있는 공고(사람인 공고 ID 기준)는 다시 저장하지 않는다 |
| F9 | 시트에 공고 ID와 저장 시각 열을 추가한다 |
| F10 | 실행이 끝나면 아래 집계 기준으로 네 가지 수를 출력하고, 실패한 공고는 회사명·직무·실패 단계(요약/저장)를 함께 출력한다 |
| F11 | 지역·직무·경력 이름을 알 수 없으면 API를 부르기 전에 멈추고, 입력한 값과 쓸 수 있는 이름 목록을 출력한다 |

### 집계 기준 (F10)

| 항목 | 뜻 |
| --- | --- |
| 가져옴 | 필터를 거친 뒤 처리 대상이 된 공고 수 |
| 새로 저장 | 요약하고 시트에 저장까지 끝난 공고 수 |
| 건너뜀 | 시트에 이미 있어서 요약·저장하지 않은 공고 수 |
| 실패 | 요약 또는 시트 저장 중 오류가 난 공고 수 |

- 가져옴 = 새로 저장 + 건너뜀 + 실패 가 항상 성립한다.
- 실패한 공고는 시트에 넣지 않는다. 시트에 없으므로 다음 실행 때 다시 처리된다.
- 사람인 API 호출 자체가 실패하면 집계 없이 오류 메시지를 출력하고 끝낸다 (키는 메시지에 넣지 않음).

## 비기능 요구사항

| ID | 내용 |
| --- | --- |
| N1 | v0.1의 N1~N4(키 관리, 무료 개발, 모델 교체, 서버 없음)를 그대로 지킨다 |
| N2 | 이미 저장된 공고는 AI 요약도 하지 않는다 (무료 사용량 절약) |
| N3 | 공고 하나의 요약이나 저장이 실패해도 나머지는 계속 처리한다 |
| N4 | 가짜 데이터 테스트를 `tests/`에 pytest로 둔다 |

## 하지 않는 것

- 적합도 점수 (v0.3)
- 학력·고용형태 필터
- 여러 페이지 조회 (`start` 파라미터). 조건이 좁으면 요청한 개수보다 적게 나올 수 있다
- 메일 알림, 웹 화면

## 확인한 것

[사람인 채용공고 검색 API 문서](https://oapi.saramin.co.kr/guide/job-search) 기준 (2026-10-19 확인).

- `count`는 기본 10, 최대 110. 더 받으려면 `start`(0부터 시작하는 페이지 번호)로 다시 호출해야 한다.
- 요청 조건에 경력 항목이 없다. 경력은 응답의 `experience-level`(코드 1 신입, 2 경력, 3 신입/경력, 0 경력무관, 연차 `min`·`max`)으로만 알 수 있다.
- 지역은 `loc_mcd`(1차 지역), 직무는 `job_mid_cd`(상위 직무)·`job_cd`(직무)로 거른다.
- 하루 호출 수 제한이 있다(오류 코드 4). 정확한 횟수는 문서에 없다.
